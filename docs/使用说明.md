# 使用说明

## 一、访客：扫码下载

1. 用手机相机/微信扫描资源对应的二维码；
2. 打开详情页，屏幕底部就是**下载按钮**（固定底栏，单手可点）；
3. 打开页面时会自动测速（Pages / Raw / CDN 三条线路并发探测），**默认使用最快的线路**，按钮下方会显示所选线路与耗时；结果缓存 10 分钟；
4. 若下载仍慢，点“下载慢？切换其它线路”展开备用链接复制直链；
5. “分享二维码”按钮可展开二维码并保存 PNG（访客来自扫码，默认折叠）。

## 访问控制（谁能看到什么）

| 角色 | 能看到 |
| --- | --- |
| 访客 | 只能凭二维码/直链打开**某个资源的详情页**并下载；首页不列资源，详情页也不显示返回列表入口 |
| 管理员 | 本机保存 GitHub 令牌后，首页可浏览/搜索全部资源，`#/admin` 可上传、编辑、权重、删除 |

资源地址用 8 位随机 id（如 `x3xfzvcp`），不公开索引、无法枚举；已生成的二维码与链接不受影响。

> **局限**：GitHub Pages 本身无法做访问鉴权，公开仓库里的 `data/resources.json` 理论上仍可被直接读取。
> 若要彻底隐藏：①仓库转私有，②站点搬到支持鉴权的托管（Cloudflare Pages + Access 等）。
> 注意：**免费账号的私有仓库不支持 Pages**，私有仓库的文件也无法匿名直链下载（需改走对象存储签名 URL）。

## 二、管理员：网页管理端

打开 `https://jisyu.github.io/Web_Server_Resource/#/admin`。

### 1. 连接 GitHub

- 创建 Fine-grained 令牌：权限 **Contents: Read and write**，仅授权本仓库；
- 粘贴到"个人访问令牌"输入框，可勾选"在本机保存"（写入浏览器 localStorage）；
- 连接成功后状态变为 `已连接 @用户名`，此时上传、编辑、删除按钮可用；
- 未连接时为只读模式，可查看清单但无法改动。

### 2. 上传资源

1. 在"上传资源"区点击或拖入文件（可多选）；
2. 选择分类（或自动识别），可填名称、版本、描述、权重；
3. 点"开始上传"，逐文件上传到仓库 `files/<分类>/` 目录；
4. 上传完成后**必须点"保存全部改动"**，否则清单里不会有这些资源。

每个文件一次提交，清单改动合并为一次提交。

### 3. 编辑与权重管理

- 直接在表格里改名称、分类、版本；
- **权重**：数字越大越靠前，可用 ▲/▼ 快速 ±10；
- **置顶**：勾选后永远排在最前；
- **显示**：取消勾选即下架，文件保留但不在列表展示（仍可用原详情页链接访问）；
- 改完后点"保存全部改动"提交；点"撤销未保存改动"可回退到上次保存的状态。

### 4. 删除

行内"删除" → 确认 → 同时删除仓库文件与清单条目（会立即提交）。

### 5. 二维码

- 行内"二维码"：可查看、下载 PNG/SVG、复制扫码链接与直下链接；
- 底部"导出全部二维码"：打包下载 ZIP（全部可见资源）；
- 命令行批量生成：`node tools/manage.mjs qr` → 输出到 `qr/<id>.svg`。

## 三、本地工具

```bash
node tools/serve.mjs          # 本地预览 http://127.0.0.1:8080
node tools/manage.mjs list    # 查看清单
node tools/manage.mjs import <目录> -r --category=apk --weight=100
node tools/manage.mjs sync --prune     # 扫描 files/ 补齐或清理清单
node tools/manage.mjs set <id> --name=xx --weight=200 --visible=true
node tools/manage.mjs rm <id> --file   # 连文件一起删除
node tools/manage.mjs qr               # 批量生成二维码 SVG
```

批量导入与超大文件（>100 MB）建议用本地工具 + `git push`，不走网页 API。

## 四、常见问题

| 现象 | 原因 / 处理 |
| --- | --- |
| 保存后列表没变 | Pages 有生效延迟（数十秒~数分钟）；管理页列表点"刷新"可强制拉取最新清单 |
| 上传失败 100MB | Contents API 上限，改用本地导入后 `git push` |
| 提示 401/403 | 令牌无效、过期或权限不足，重新生成并确认 Contents: Read and write |
| 提示 409 | 清单被别处改过（sha 冲突），点"刷新"后再保存 |
| 扫码后下载慢 | 页面已自动测速选最快线路；仍慢可展开「下载慢？查看各线路速度 / 手动切换」挑一条，点“重新测速” |
| git clone 很快、网页下载很慢 | clone 走本机代理（如 127.0.0.1:7897），浏览器/手机是**直连 GitHub**，国内直连常被限速到几十 KB/s |

### 让国内下载稳定满速（推荐配置镜像）

编辑 `assets/config.js` 的 `CONFIG.mirrors`，填入镜像前缀即可参与测速并自动成为主下载链接：

```js
mirrors: [
  'https://gitee.com/jisyu/Web_Server_Resource/raw/main/' // Gitee：导入本仓库并开启强制同步，国内满速
  // 也可用对象存储/CDN 根地址：'https://cdn.example.com/'
]
```

国内常用做法：在 Gitee「从 GitHub/GitLab 导入仓库」导入本仓库并开启同步，然后把上面那行填进去；文件目录结构与 GitHub 一致，二维码与页面都不用改。
| 二维码扫不出 | 用"复制扫码链接"核对；本地预览时生成的码指向线上地址，线上需先发布 |

## 五、安全提醒

- 仓库为公开仓库，清单条目 id 为随机 8 位，避免被枚举；
- 令牌只保存在本机，公用电脑不要勾选"记住"；
- 下架（取消"显示"）只是不在列表展示，知道链接的人仍可下载；真正私密的文件不要放公开仓库。
