# Web 资源服务器 设计文档（框架稿）

> 状态：**已核对并实施**（D1~D4 全部采用推荐方案）。
> 架构为「静态站点 + GitHub API 管理端」：站点无后端、无构建，读走 CDN/raw，写走 GitHub REST API。

## 1. 目标与硬约束

| 项 | 内容 |
| --- | --- |
| 业务目标 | 用户扫描二维码 → 打开网页 → 下载事先上传的资源文件 |
| 功能目标 | 资源的 上传 / 下载 / 编辑 / 权重排序（含删除、上下架） |
| 托管要求 | 托管在 GitHub（账号 `jisyu`） |
| 硬约束 | GitHub Pages **只提供静态文件托管，不能运行任何后端代码**（无 PHP / Node / 数据库 / 服务端会话） |
| 推论 | **不能做成传统"Web 服务器"**，必须采用「静态站点 + GitHub API 管理端」的无后端架构：站点本身是纯 HTML/JS，所有写操作（上传、改清单、删文件）通过 GitHub REST API 或本地 git 完成 |

## 2. 总体架构（无后端三层）

```
                 ┌──────────────── 二维码 ────────────────┐
用户扫码  ──▶  https://jisyu.github.io/Web_Server_Resource/#/r/<id>
                            │
   ┌────────────────────────▼───────────────────────────────┐
   │  ① 站点层 GitHub Pages（纯静态，无构建、无框架依赖）      │
   │     列表页 index.html / 详情页 #/r/<id> / 管理页 #/admin  │
   └──────────────┬───────────────────────────┬─────────────┘
           读（fetch）                    写（需 PAT）
                  │                           │
   ┌──────────────▼───────────────────────────▼─────────────┐
   │  ② 存储层 GitHub 仓库 jisyu/Web_Server_Resource          │
   │     data/resources.json   ← 资源清单（唯一数据源）        │
   │     files/<分类>/<文件>    ← 资源实体                     │
   │     qr/<id>.png          ← 预生成二维码                   │
   └─────────────────────────────────────────────────────────┘
                  │
   ┌──────────────▼─────────────────────────────────────────┐
   │  ③ 加速/直链：CDN(jsDelivr) 或 raw.githubusercontent     │
   └────────────────────────────────────────────────────────┘
```

- **访问域名**：`https://jisyu.github.io/Web_Server_Resource/`（仓库 `jisyu/Web_Server_Resource`）
- **仓库路径**：`E:\workspace\KongSon\WeChat_Project\Uni-App\Web_Server_Resource`
- **管理入口两种形态**（见决策点 D2）：浏览器管理页直连 GitHub API，**或** 本地 Node CLI + git。

## 4. 数据模型（data/resources.json）

```json
{
  "version": 1,
  "updatedAt": "2026-10-24T10:00:00Z",
  "categories": ["apk", "doc", "image", "other"],
  "items": [
    {
      "id": "a1b2c3d4",                  // 8 位随机短 id，出现在 URL 与二维码中
      "name": "Light_RGBYW v1.1.0",      // 显示名
      "fileName": "Light_RGBYW-release.apk",
      "path": "files/apk/Light_RGBYW-release.apk",   // 仓库内相对路径
      "category": "apk",
      "tags": ["Android", "正式版"],
      "description": "灯光控制 App 正式版安装包",
      "version": "1.1.0",
      "size": 33554432,                  // 字节，写入时记录
      "sha1": "…",                       // 可选，用于校验与去重
      "mime": "application/vnd.android.package-archive",
      "weight": 100,                     // 权重：越大越靠前；支持置顶
      "pinned": false,                   // true 时永远排最前
      "visible": true,                   // 下架仍保留文件，只是不在列表展示
      "releaseNotes": "修复 BLE 连接稳定性",
      "createdAt": "2026-10-24T10:00:00Z",
      "updatedAt": "2026-10-24T10:00:00Z"
    }
  ]
}
```

**下载链接不入库，按规则推导**，避免仓库迁移/改名后失效：

- Pages 同源（**默认**，国内最稳）：`https://jisyu.github.io/Web_Server_Resource/<path>`
- Raw（备用）：`https://raw.githubusercontent.com/jisyu/Web_Server_Resource/main/<path>`
- CDN（备用，jsDelivr 国内不稳定）：`https://cdn.jsdelivr.net/gh/jisyu/Web_Server_Resource@main/<path>`

三者由 `assets/config.js` 统一推导，`CONFIG.downloadPrimary` 可切换默认链路；详情页把三条全部列出供切换。

## 5. 页面与交互设计

| 视图 | 路由 | 内容 |
| --- | --- | --- |
| 列表页 | `#/` | 卡片网格：名称/分类/版本/大小/更新时间/下载按钮/二维码按钮；顶部搜索框、分类与标签筛选；排序 = 置顶优先 → 权重降序 → 更新时间降序 |
| 详情页（扫码落地页） | `#/r/<id>` | 大标题 + 描述 + 版本 + 大小 + 更新说明 + **主下载按钮** + 备用直链 + 内嵌二维码（可另存）+ 下载计数（本地 localStorage 统计，可选） |
| 管理页 | `#/admin` | PAT 登录 → 资源表格（内联编辑名称/描述/版本/权重/分类/上下架）→ 拖拽或输入框调权重 → 上传区（拖放/多选，显示进度）→ 删除（文件 + 清单 + 二维码）→ 保存并提交 → 二维码生成与批量导出 ZIP |

- 全部为 **hash 路由**：GitHub Pages 无 URL 重写，hash 可避免刷新 404。
- 移动端优先（扫码场景绝大多数在手机），桌面自适应两列/三列。
- 管理页未登录 PAT 时自动降级为**只读预览**，防止误操作。

## 6. 关键流程

### 6.1 上传（浏览器管理页）

1. 粘贴 Fine-grained PAT（权限 `Contents: read+write`，仅本仓库），可选"记住（localStorage）"。
2. 选择/拖入文件 → 计算大小 → 按 `<分类>/<文件名>` 生成目标路径（重名自动追加 `-1`）。
3. `PUT /repos/jisyu/Web_Server_Resource/contents/{path}`（base64 内容 + commit message）→ 得到文件 sha。
4. 生成二维码 PNG，上传至 `qr/<id>.png`。
5. `GET /contents/data/resources.json` 取得当前内容 + sha → 追加条目 → `PUT` 覆盖（带 sha，乐观锁防冲突）。
6. 界面即时刷新，提示"已提交，Pages 稍后 1~2 分钟生效"。

### 6.2 扫码下载

二维码内容 = `https://jisyu.github.io/Web_Server_Resource/#/r/<id>`  → 详情页 → 点击下载 → 浏览器跳转 CDN/直链 URL 完成下载（APK 直接触发安装）。
另提供"**直下码**"选项：二维码直接编码文件下载 URL，扫码后不经过网页立即下载。

### 6.3 编辑 / 权重 / 删除

- 编辑：只改 `resources.json` 条目字段，一次批量提交（多条改动合并为 1 个 commit）。
- 权重：表格内数字输入 / 上下移动按钮 / 拖拽排序；保存时整体写回清单。
- 删除：三连删（实体文件 + `qr/<id>.png` + 清单条目），需要文件 sha，二次确认。

### 6.4 本地 CLI（备选通道）

`node tools/manage.mjs import <目录>` 批量把本地文件复制进 `files/` 并写入清单；
`node tools/manage.mjs qr` 批量重建二维码；`node tools/manage.mjs sync` = 扫描目录重建清单。
适合批量导入、超大文件（走 git 而非 API）、以及断网整理。

## 7. 技术选型

| 维度 | 选择 | 理由 |
| --- | --- | --- |
| 构建 | **无构建**（原生 ES Module，直接提交源码） | Pages 无需编译，改完即生效，避免 Node 依赖 |
| 框架 | 无（原生 JS + 少量自写工具函数） | 页面少、逻辑轻，避免引入构建链 |
| 二维码 | vendored 的 QR 生成库（BSD/MIT），**不依赖 CDN 运行时** | 国内网络访问 CDN 不稳定；离线可用 |
| 存储 API | GitHub REST API v2022-11-28（Contents / Git Trees） | 唯一可用的无后端写入通道 |
| 样式 | 手写 CSS + CSS 变量，深色/浅色自适应 | 无依赖、体积小 |
| 预览 | `node tools/serve.mjs`（零依赖 http 模块） | 本地调试与 Pages 行为一致 |

## 8. 平台限制与应对

| 限制 | 数值 | 应对 |
| --- | --- | --- |
| Contents API 单文件 | 100 MB（建议 ≤ 50 MB） | 超限走本地 CLI + git |
| jsDelivr 单文件 | 约 50 MB（大文件不稳定） | 大文件自动改用 raw/Pages 直链 |
| 仓库体积 | 软上限 1 GB | 定期清理历史版本；超大文件改 Release 附件 |
| Pages 站点 | 1 GB / 月带宽 100 GB | 大文件走 CDN；必要时 Release 附件分流 |
| API 速率 | 5000 次/小时（PAT） | 合并提交，减少请求 |
| Pages 生效延迟 | 数十秒~数分钟 | 页面提示"稍等生效"，详情页不强依赖清单（可用 raw 直链） |

## 9. 安全设计

- PAT 仅存本机 localStorage，UI 明示其权限范围，提供一键清除；不在 URL / 日志中暴露。
- 管理页可选"口令门槛"（口令的 SHA-256 存仓库，仅防误入，非真正鉴权）。
- 渲染统一走 `textContent` / 白名单，禁止 `innerHTML` 拼接用户数据（防 XSS）。
- 上传路径消毒：文件名去路径字符（`/\..:` 等）、限制扩展名白名单、重名冲突自动改名。
- 仓库整体公开时，靠随机 id 保证清单条目 URL 不可枚举（详见决策点 D4）。
